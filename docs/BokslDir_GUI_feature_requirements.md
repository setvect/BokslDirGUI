# BokslDir GUI 상세 기능 요구사항

- 작성일: 2026-06-12
- 대상 산출물: 기존 터미널/TUI 기반 BokslDir의 개발 내용을 기준으로 한 신규 GUI 파일 매니저 기능 요구사항
- 범위: 언어/프레임워크 결정 전 기능 요구사항 정의
- 전제: 기존 Rust/TUI 로직 재사용 여부는 결정 기준에서 제외한다. 단, 기존 개발 산출물이 제공하는 기능·동작·UX 의도는 신규 GUI 요구사항의 근거로 사용한다.

---

## 1. 근거와 해석 원칙

### 1.1 근거 우선순위

1. 실제 구현 코드 `BokslDir/src/**`
2. 저장소 운영 가이드 `BokslDir/AGENTS.md`
3. 제품 문서 `BokslDir/docs/PRD.md`, `BokslDir/docs/Requirements.md`, `BokslDir/docs/User-Manual.md`
4. README

기존 저장소의 지침은 “문서 간 상태가 어긋날 수 있으므로 동작 판단은 코드 기준”이라고 명시한다. 따라서 이 문서는 **구현 완료로 확인되는 기능**과 **문서에는 있지만 코드 근거가 약한 후보 기능**을 분리한다.

### 1.2 GUI 전환 해석

- 기존 TUI의 “키보드 중심 듀얼 패널 파일 매니저” 정체성은 GUI에서도 유지한다.
- GUI에서는 키보드 단축키뿐 아니라 마우스, 컨텍스트 메뉴, 드래그 앤 드롭, 시스템 파일 다이얼로그 같은 데스크톱 상호작용을 1급 기능으로 추가한다.
- 기존의 터미널 제약(80x24 최소 크기, raw mode, IME 경고 등)은 GUI에서는 그대로 이식하지 않고, “작은 창 대응”, “한글 입력/표시 안정성” 요구사항으로 재해석한다.

## 2. 제품 목표

### PRD-1. 듀얼 패널 중심의 고속 파일 관리

신규 GUI 앱은 좌/우 두 패널을 동시에 보여주며, 활성 패널 기준으로 파일 탐색·선택·작업을 수행해야 한다.

**수용 기준**

- 앱 실행 시 기본 화면은 좌/우 듀얼 패널 구조를 제공한다.
- 사용자는 활성 패널을 명확히 구분할 수 있다.
- 복사/이동 같은 양방향 파일 작업은 “활성 패널 → 반대 패널” 흐름을 기본값으로 제안한다.
- 단일 패널 보기 또는 좁은 창 대응 모드를 제공한다.

### PRD-2. 키보드 숙련자와 GUI 일반 사용자를 모두 지원

기존 BokslDir의 Vim/F키 기반 속도감을 유지하되, GUI에서는 메뉴·툴바·마우스 조작으로도 모든 주요 기능에 접근할 수 있어야 한다.

**수용 기준**

- 주요 기능은 메뉴/버튼/컨텍스트 메뉴/단축키 중 최소 2개 이상의 접근 경로를 가진다.
- 기존 핵심 단축키(`j/k/h/l`, `Tab`, `y/x/d/D`, `/`, `.`, `tn/tx/tt`, `zc/zx/za`, `?`)는 가능한 한 호환 또는 사용자 설정 가능한 형태로 제공한다.
- 단축키 도움말/검색 UI를 제공한다.

### PRD-3. 파일 작업의 안전성과 복구 가능성 우선

파일 삭제·이동·덮어쓰기·압축 해제 같은 위험 작업은 명시적인 확인, 충돌 처리, 진행률, 취소, 오류 요약을 제공해야 한다.

**수용 기준**

- 모든 장시간 파일 작업은 UI를 블로킹하지 않는다.
- 작업 진행률은 파일 수, 바이트 수, 현재 항목, 속도, 예상 남은 시간을 표시한다.
- 사용자는 작업 중 취소할 수 있다.
- 충돌 발생 시 덮어쓰기/건너뛰기/모두 덮어쓰기/모두 건너뛰기/취소를 선택할 수 있다.
- 작업 완료 후 양쪽 패널이 최신 상태로 갱신된다.

## 3. 기능 요구사항

### FR-1. 앱 시작과 초기 경로

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-1.1 | 앱은 실행 시 좌/우 패널을 초기 경로로 로드해야 한다. | Must |
| FR-1.2 | 시작 경로가 지정되면 좌/우 패널 모두 해당 경로에서 시작해야 한다. | Must |
| FR-1.3 | 시작 경로가 없으면 이전 종료 시점의 히스토리/상태를 복원해야 한다. | Should |
| FR-1.4 | 시작 경로가 유효하지 않으면 안전한 기본 경로 또는 직전 상태로 fallback해야 한다. | Must |
| FR-1.5 | GUI 앱은 최근 작업 폴더 또는 홈 디렉토리를 빠르게 선택할 수 있는 시작 옵션을 제공할 수 있다. | Could |

**수용 기준**

- 유효한 디렉토리 경로로 실행하면 두 패널이 같은 경로를 표시한다.
- 유효하지 않은 경로는 오류로 앱을 종료하지 않는다.
- 상태 복원은 손상된 설정 파일을 만나도 앱 실행을 막지 않는다.

### FR-2. 메인 레이아웃과 패널

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-2.1 | 메인 화면은 상단 메뉴/도구 영역, 좌·우 파일 패널, 상태바, 명령/힌트 영역을 포함해야 한다. | Must |
| FR-2.2 | 좌·우 패널은 각각 독립적인 현재 경로, 선택 상태, 스크롤, 정렬, 필터, 히스토리를 가진다. | Must |
| FR-2.3 | 활성 패널은 테두리/헤더/강조 색 등으로 명확히 표시해야 한다. | Must |
| FR-2.4 | 창 크기에 따라 컬럼과 패널 표시를 반응형으로 조정해야 한다. | Must |
| FR-2.5 | 사용자는 듀얼 패널/단일 패널 보기를 전환할 수 있어야 한다. | Should |
| FR-2.6 | 사용자는 패널 비율을 50:50, 70:30, 30:70 등으로 조정할 수 있어야 한다. | Should |
| FR-2.7 | 너무 작은 창에서는 기능이 깨지지 않고 최소 창 크기 안내 또는 축약 UI를 제공해야 한다. | Must |

**수용 기준**

- 패널마다 경로 제목, 탭 개수, 파일 리스트, 스크롤 상태가 표시된다.
- 좁은 창에서도 파일명은 잘리고 앱이 패닉/크래시하지 않는다.
- 단일 패널 모드에서 `Tab` 또는 GUI 컨트롤로 좌/우 패널을 전환할 수 있다.

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-3.1 | 디렉토리 내용을 읽어 파일/디렉토리/심볼릭 링크/실행 파일을 구분해야 한다. | Must |
| FR-3.2 | 각 항목은 이름, 크기, 수정일, 생성일, 권한, 소유자/그룹 등 가능한 메타데이터를 표시할 수 있어야 한다. | Must |
| FR-3.3 | 디렉토리는 기본적으로 파일보다 먼저 표시해야 한다. | Must |
| FR-3.4 | 상위 디렉토리 이동 항목(`..`) 또는 동등한 GUI 탐색 컨트롤을 제공해야 한다. | Must |
| FR-3.5 | 숨김 파일 표시/숨김을 토글할 수 있어야 한다. | Must |
| FR-3.6 | 파일 타입별 아이콘과 색상을 제공해야 한다. | Must |

| FR-3.9 | 권한 부족·존재하지 않는 경로·깨진 심볼릭 링크 같은 오류는 항목 단위 또는 패널 단위로 명확히 표시해야 한다. | Must |

**수용 기준**

- 파일 타입별 시각 구분이 가능하다.
- 숨김 파일 토글 시 양쪽 패널 또는 활성 패널 정책이 명확히 적용된다.
- 권한이 없는 폴더 진입 시 앱이 종료되지 않고 오류 메시지를 표시한다.

- 경로 입력창에 일부 경로를 입력하면 후보 목록이 표시된다.

- 선택된 여러 파일에 복사/이동/삭제/압축 작업이 적용된다.
- 선택 상태와 현재 포커스가 시각적으로 혼동되지 않는다.

- 작업 완료 후 선택 상태가 초기화된다.

## 7. 검증 기준

### 7.1 기능 테스트 시나리오

1. 홈 디렉토리에서 앱을 실행하고 좌/우 패널이 모두 렌더링되는지 확인한다.
2. 좌측 패널에서 하위 폴더 진입 후 우측 패널 상태가 유지되는지 확인한다.
3. 여러 파일을 선택하고 반대 패널로 복사한다.
4. 동일 파일명 충돌에서 “건너뛰기”와 “모두 덮어쓰기”가 각각 동작하는지 확인한다.
5. 큰 파일 복사 중 진행률과 취소가 동작하는지 확인한다.
6. 휴지통 삭제와 영구 삭제가 서로 다른 확인 흐름을 사용하는지 확인한다.
7. 한글 파일명 파일을 생성/이름 변경/필터링/삭제한다.
8. `*.md` 필터와 이름 정렬/크기 정렬을 확인한다.
9. 북마크 추가 후 재시작하여 복원 여부를 확인한다.
10. zip 압축 생성, 미리보기, 해제를 확인한다.
11. 한국어/영어 전환과 테마 전환 후 재시작 복원을 확인한다.
12. OS 기본 앱 열기가 플랫폼별로 동작하는지 확인한다.

### 7.2 회귀 테스트 우선순위

- 파일 작업: 복사/이동/삭제/충돌/취소
- 경로 처리: 상대/절대/홈/공백/한글/특수문자
- 압축 해제 보안: `../` 경로 차단
- 설정 복원: 정상/손상/구버전 설정 파일
- 대량 디렉토리: 렌더링/스크롤/정렬/필터

## 9. 미확정/주의 사항

- 기존 문서에는 파일 내용 검색, 일괄 이름 변경, 단축키 커스터마이징, 파일 연결 설정, 디스크 사용량, 파일 비교가 포함되어 있으나, 현재 코드 근거가 강하지 않아 후속 검토 기능으로 분리했다.
- 기존 구현의 OS 기본 앱 열기는 macOS 우선이므로 GUI 요구사항에서는 Windows/Linux까지 확장해야 한다.
- 기존 TUI의 터미널 에디터/명령 실행은 GUI 보안·UX 측면에서 그대로 옮기기보다 외부 앱 열기/터미널에서 열기/명령 실행 옵션으로 재설계해야 한다.
- 언어와 프레임워크 선택은 이 문서 범위가 아니며, 이 요구사항을 만족하기 쉬운 플랫폼 API, 파일 시스템 권한 모델, 패키징/업데이트 전략을 별도로 평가해야 한다.
