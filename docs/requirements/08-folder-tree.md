## 1. 범위와 근거

### 1.1 범위

- 대상: 로컬 폴더, SFTP 원격 폴더, 패널이 열고 있는 압축 파일 내부 폴더
- 위치: 기존 TUI 기능 동등성 범위 밖의 GUI 확장 기능
- 우선순위 표기: 기존 요구사항과 같은 Must·Should·Could, 폴더 트리 안의 상대 중요도 의미(축소 범위 의미 아님)
- 범위 밖, 별도 결정: 두 패널이 함께 쓰는 단일 트리, 트리 안 다중 선택, 표준 위치(홈·문서·다운로드) 묶음

### 1.2 근거

- 기존 TUI: 폴더 트리 기능 없음(`BokslDir` 코드·문서에 트리 화면 없음)
- 현재 GUI: 사이드바 요구사항 [FR-25](03-navigation-search-organization.md#fr-25-사이드바와-빠른-위치) 존재, 트리 화면 없음
- 재사용한 기존 구조

## 2. 설계 원칙

- 키보드 중심 조작 유지: `Tab`의 좌우 패널 전환 의미 보존, 트리는 별도 키로 오감
- 메뉴·단축키·우클릭 메뉴·드래그의 공통 action registry와 작업 실행 경로 사용
- 트리는 탐색 보조 화면: 패널 경로·탭·히스토리·선택 상태를 소유하지 않고 패널 이동은 기존 경로 사용
- 파일 시스템 변경은 기존 작업 흐름(확인 창·진행률·취소·오류 요약) 그대로, 트리 전용 변경 명령 없음
- 읽기 비용 최소화: 펼칠 때 한 단계만 읽고, 패널이 이미 읽은 목록으로 현재 폴더 갱신

## 3. 기능 요구사항

### FR-42. 패널 폴더 트리

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-42.1 | 패널마다 폴더 트리 표시를 따로 전환(경로 줄 버튼·`t r`·보기 메뉴), 표시 여부와 폭을 설정에 저장 | Must |
| FR-42.2 | 트리는 경로 줄과 상태 줄 사이 본문 왼쪽, 경계선 끌기로 폭 조절, 목록은 패널 폭의 60% 이상 유지 | Must |
| FR-42.3 | 맨 위 항목은 드라이브·볼륨(원격은 서버 루트), 폴더만 이름순, 펼칠 때 한 단계만 읽기, 숨김 폴더는 패널의 숨김 파일 설정 따름 | Must |
| FR-42.4 | 패널이 어디로 이동하든 트리가 그 경로까지 펼쳐 표시, 트리 클릭은 패널 이동 | Must |
| FR-42.5 | SFTP 패널은 서버 루트부터, 압축 내부를 보는 패널은 열린 압축 파일을 가상 폴더로 표시 | Must |
| FR-42.6 | 키보드: `g t` 목록 ↔ 트리, 화살표·`h`·`j`·`k`·`l` 이동·펼치기, 커서가 멈추면 패널이 따라감, 파일 작업 키는 트리 커서 폴더 대상 | Must |
| FR-42.7 | 마우스: 클릭·화살표 클릭·더블클릭·우클릭 메뉴(반대 패널에서 열기 포함)·드래그 앤 드롭(트리 폴더로 놓기, 트리 폴더 끌기) | Must |
| FR-42.8 | 링크 폴더는 펼치지 않고 실제 위치로 이동, 읽기 실패 폴더는 줄에 표시, 폴더 수천 개도 끊김 없이 표시 | Should |

**수용 기준**

- 왼쪽 트리를 켜도 오른쪽 트리는 그대로, 다시 실행해도 패널별 표시 여부·폭 유지
- 트리를 켜면 목록 열 구성이 목록 영역 폭 기준으로 바뀜(좁은 패널 날짜 형식 포함)
- 패널 이동(Enter·뒤로·경로 입력·북마크·탭 전환) 뒤 트리에서 현재 폴더가 보이고 선택 표시
- 트리 커서를 연달아 옮기면 멈춘 폴더만 읽고 히스토리에 남김
- 맨 위 항목(드라이브·볼륨·서버 루트)과 열린 압축 파일은 복사·이동·삭제·이름 바꾸기 대상에서 제외
- 폴더를 자기 자신이나 하위 폴더에 놓는 드래그는 차단 표시
- 트리에서 패널의 현재 폴더를 지우거나 옮기거나 이름을 바꾸면 패널은 남아 있는 가장 가까운 상위 폴더로 이동
- SFTP 연결이 끊긴 동안 트리는 흐리게 표시, 다시 연결되면 펼친 폴더를 다시 읽음

## 4. 화면과 조작

### 4.1 메뉴와 단축키

| 액션 ID | 메뉴 | 단축키 | 동작 |
| --- | --- | --- | --- |
| `view.toggleFolderTree` | 보기 > 폴더 트리 | `t r` | 활성 패널의 트리 표시 전환, 상태 줄에 "폴더 트리 · 패널 · 켜짐/꺼짐" |
| `view.focusFolderTree` | 보기 > 트리·목록 전환 | `g t` | 활성 패널의 목록 ↔ 트리 키보드 이동, 트리가 꺼져 있으면 켜면서 이동 |
| `nav.openInOtherPanel` | 이동 > 반대 패널에서 열기 | 없음 | 목록·트리의 폴더를 반대 패널에서 열기, 우클릭 메뉴에도 표시 |

- 경로 줄 맨 왼쪽 `◧` 버튼: 그 패널의 트리 표시 전환, 켜짐 상태 표시(`aria-pressed`)

### 4.2 키보드(트리에 키보드가 있을 때)

| 키 | 동작 |
| --- | --- |
| `↑`·`↓`, `k`·`j` | 커서 이동, 약 0.3초 멈추면 패널이 그 폴더로 이동 |
| `PageUp`·`PageDown`, `Cmd/Ctrl+U`·`Cmd/Ctrl+D`, `Home`·`End`, `gg`·`G` | 쪽 단위·처음·끝 이동 |
| `→`·`l` | 펼치기, 이미 펼쳤으면 첫 하위 폴더로 |
| `←`·`h` | 접기, 이미 접혔으면 상위 폴더로 |
| `Enter` | 대기 중인 이동을 바로 실행하고 목록으로 |
| `Esc` | 대기 중인 이동을 취소하고 목록으로 |
| `Tab` | 좌우 패널 전환(상대 패널 목록으로), 트리 키보드 해제 |
| 파일 작업 키(`F5`·`F6`·`d`·`F2`·`i`·`Cmd/Ctrl+C` 등) | 트리 커서 폴더 대상, 기존 확인 창 그대로 |
| 현재 폴더 대상 키(`F7`·`Cmd/Ctrl+V`·정렬·필터 등) | 패널의 현재 폴더 대상(따라간 뒤에는 트리 커서 폴더) |
| 선택 키(`Space`·`Cmd/Ctrl+A` 등) | 트리에서는 사용 불가 안내 |
| `Shift+F10`·메뉴 키 | 트리 커서 폴더의 우클릭 메뉴 |

- 트리에 키보드가 있는 동안 목록 커서는 비활성 패널처럼 테두리만 표시
- 목록 영역을 누르면 키보드가 목록으로 복귀

### 4.3 마우스

| 조작 | 동작 |
| --- | --- |
| 줄 클릭 | 그 폴더로 바로 이동, 트리에서 계속 키보드 조작 |
| 펼침 화살표 클릭 | 이동 없이 펼치기·접기 |
| 더블클릭 | 펼치기·접기 |
| 우클릭 | 그 폴더 대상 메뉴(맨 위 항목·열린 압축 파일은 열기·반대 패널에서 열기만) |
| 목록 항목을 트리 폴더에 놓기 | 그 폴더로 복사·이동(기존 놓기 규칙·수정키 그대로) |
| 트리 폴더 끌기 | 반대 패널·다른 트리 폴더·OS로 끌어 놓기(맨 위 항목·열린 압축 파일 제외) |
| 끄는 동안 접힌 폴더 위에 머물기 | 약 0.7초 뒤 펼침, 트리 위아래 가장자리에서 스크롤 |
| Finder·탐색기에서 트리 폴더에 놓기 | 그 폴더로 가져오기 |
| 경계선 끌기 | 폭 조절, 놓을 때 저장(100% 배율 기준 120~800px) |

## 5. 구조

### 5.1 상태 소유

| 상태 | 소유 | 비고 |

| 읽은 폴더 모델·평탄화·경로 펼치기 | `src/ui/folderTreeModel.ts` | React·Tauri 무관 순수 함수 |
| 화면·가상 스크롤·우클릭 메뉴 | `src/ui/FolderTree.tsx` | 배치·경계선은 `FilePanel` |

### 5.2 명령

- `list_subdirs(path)`: 한 단계 하위 폴더(숨김 포함, `isHidden`으로 구분), 이름순, 폴더를 가리키는 링크 포함
  - 로컬: 파일은 종류만 보고 건너뛰어 메타데이터 미조회, 읽지 못한 항목 하나는 제외하고 나머지 반환
  - 원격: 같은 SFTP 연결로 읽고 링크 대상이 폴더인 것만 포함
- 기존 `list_dir` 미사용 이유: 파일까지 모든 항목의 메타데이터 조회, 패널 정렬·필터 인자에 묶임
- 압축 내부 폴더: 패널이 읽어 둔 압축 목록에서 계산, 추가 명령 없음

### 5.3 저장 형식

- `layout.folderTree`: `{ left: { visible, width }, right: { visible, width } }`, 기본값(숨김·220px)이면 저장 파일에서 생략
- 폭 검증: Rust `settings_service`가 120~800px 밖 값 거부(`layout.folderTree.<panel>.width`)

## 6. 설계 결정

| 결정 | 채택 | 제외 | 이유 |
| --- | --- | --- | --- |
| 트리 위치 | 각 패널 안 경로 줄 아래 왼쪽 | 두 패널 공용 트리 | 패널마다 독립 제어 요청 |
| 커서 이동 | 멈추면 패널이 따라감(탐색기 방식) | `Enter`를 눌러야 이동 | 사용자 확정(2026-11-01), 지나친 폴더는 읽지 않음 |
| 트리 키보드의 작업 대상 | 트리 커서 폴더 | 목록 선택 유지 | 사용자 확정(2026-11-01), 화면에서 보이는 커서와 대상 일치 |
| 맨 위 항목 | 드라이브·볼륨(원격은 서버 루트) | 홈·북마크 묶음 추가 | 사용자 확정(2026-11-01), 같은 폴더가 두 번 나타나는 경로 판정 모호성 회피 |
| 링크 폴더 | 펼치지 않고 실제 위치로 이동 | 링크 경로 아래로 펼치기 | 패널이 실제 경로로 정규화, 순환 링크 무한 펼침 방지 |
| 펼침 화살표 | 처음엔 모든 폴더에 표시, 읽어 보고 없으면 제거 | 하위 폴더 유무 미리 확인 | 폴더마다 추가 읽기 없이 원격·네트워크 드라이브에서도 빠름 |
| 맨 위 항목·열린 압축 파일 작업 | 이동만 허용 | 일반 폴더와 같은 작업 | 드라이브·볼륨·서버 루트 삭제·이동 오조작 방지 |
| Windows 드라이브 표기 | 위치 목록의 `C:\`를 패널의 정규화 경로(`\\?\C:\`)와 같은 폴더로 취급 | 별도 항목 | 같은 드라이브가 두 번 나타나는 문제 방지 |

### 8.2 함께 고친 점

- 키보드 메뉴 키(`Shift+F10`)가 앱 시작 때의 커서 줄을 기준으로 메뉴를 열던 문제: 키 처리기가 첫 렌더의 패널 상태를 계속 참조, 매 렌더 갱신되는 키보드 상태에서 커서 줄을 읽도록 수정
- 패널의 현재 폴더가 없어졌을 때 사라진 폴더의 목록과 오류만 남던 동작: 새로고침이 `not_found`·`not_directory`로 실패하면 남아 있는 가장 가까운 상위 폴더로 이동(트리·반대 패널·다른 프로그램의 삭제·이동·이름 변경 공통), 연결 끊김 등 다른 오류는 기존대로 유지
- 목록 끌기에도 폴더를 자기 자신이나 하위 폴더(예: 반대 패널이 그 폴더 안)에 놓는 경우 차단 표시, 이전에는 Rust 검증 오류로 실패
