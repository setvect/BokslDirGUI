# 03. 탐색 조직화: 탭, 히스토리, 북마크, 경로, 검색, 사이드바

## FR-11. 탭

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-11.1 | 좌/우 패널은 각각 탭을 가질 수 있어야 한다. | Must |
| FR-11.2 | 새 탭은 현재 패널 상태를 복제해 생성하고 활성화해야 한다. | Should |
| FR-11.3 | 탭 닫기를 지원하되 마지막 탭은 닫지 않아야 한다. | Must |
| FR-11.4 | 탭 목록 보기와 특정 탭 전환을 지원해야 한다. | Must |
| FR-11.5 | 탭 제목은 현재 경로의 마지막 이름 또는 루트 경로로 표시해야 한다. | Should |
| FR-11.6 | 패널별 최대 탭 수 정책을 제공해야 한다. 기존 구현 기준은 패널당 5개다. | Should |
| FR-11.7 | GUI 탭바에서 클릭 전환, 닫기 버튼, 드래그 재정렬을 지원할 수 있다. | Should |

**수용 기준**

- 좌측 탭과 우측 탭은 서로 독립적으로 전환된다.
- 탭이 2개 이상일 때 패널 제목 영역에 탭 개수 또는 탭바가 표시된다.

## FR-12. 디렉토리 히스토리

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-12.1 | 패널별 방문 디렉토리 히스토리를 저장해야 한다. | Must |
| FR-12.2 | 뒤로/앞으로 이동을 지원해야 한다. | Must |
| FR-12.3 | 히스토리 목록 보기와 목록에서 이동을 지원해야 한다. | Must |
| FR-12.4 | 히스토리 전체 삭제 또는 현재 경로만 남기기 기능을 제공해야 한다. | Should |
| FR-12.5 | 히스토리는 재시작 후 복원되어야 한다. | Should |
| FR-12.6 | 히스토리 개수 제한을 두어 설정 파일이 무한히 커지지 않게 해야 한다. 기존 구현 기준은 패널당 100개다. | Should |
| FR-12.7 | 뒤로/앞으로 버튼의 길게 누르기 또는 드롭다운으로 히스토리 목록을 표시할 수 있다. | Should |

**수용 기준**

- 뒤로/앞으로 버튼과 단축키가 같은 히스토리 스택을 사용한다.
- 존재하지 않는 과거 경로는 복원 시 무시하거나 오류 없이 건너뛴다.

## FR-13. 북마크

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-13.1 | 현재 디렉토리를 북마크로 추가할 수 있어야 한다. | Must |
| FR-13.2 | 북마크 목록을 표시하고 선택한 경로로 이동할 수 있어야 한다. | Must |
| FR-13.3 | 북마크 이름 변경과 삭제를 지원해야 한다. | Must |
| FR-13.4 | 같은 경로의 중복 북마크 추가를 방지해야 한다. | Should |
| FR-13.5 | 중복 이름은 자동으로 고유 이름을 제안해야 한다. | Should |
| FR-13.6 | 북마크는 설정 파일에 저장되어 재시작 후 복원되어야 한다. | Must |
| FR-13.7 | GUI에서는 사이드바/즐겨찾기 영역을 제공할 수 있다. | Should |
| FR-13.8 | 북마크는 드래그 정렬, 그룹/폴더 분류를 후속으로 지원할 수 있다. | Could |

**수용 기준**

- 북마크 추가 후 목록에 즉시 표시된다.
- 삭제/이름 변경 후 설정 저장이 이루어진다.

## FR-25. 사이드바와 빠른 위치

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-25.1 | 사이드바는 홈, 데스크톱, 문서, 다운로드 등 표준 위치를 표시해야 한다. | Should |
| FR-25.2 | 사이드바는 드라이브/볼륨/마운트 포인트를 표시해야 한다. | Should |
| FR-25.3 | 사이드바는 북마크와 최근 폴더를 표시해야 한다. | Should |
| FR-25.4 | 사이드바 항목 클릭 시 활성 패널의 경로가 이동해야 한다. | Must if implemented |
| FR-25.5 | 사이드바 항목을 반대 패널로 열기 또는 새 탭으로 열기 옵션을 제공할 수 있다. | Could |
| FR-25.6 | 사이드바는 접기/펼치기와 폭 조절을 지원해야 한다. | Should |

**수용 기준**

- 사이드바 위치 클릭이 현재 활성 패널에 반영된다.
- 존재하지 않는 위치는 비활성 표시하거나 목록에서 제거한다.

## FR-26. 주소창과 Breadcrumb

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-26.1 | 패널별 breadcrumb 경로 표시를 제공해야 한다. | Must |
| FR-26.2 | breadcrumb 조각 클릭으로 해당 상위 경로로 이동해야 한다. | Must |
| FR-26.3 | 주소창 직접 입력을 제공해야 한다. | Must |
| FR-26.4 | 주소창은 `~`, 상대 경로, 절대 경로, 공백/한글 경로를 처리해야 한다. | Must |
| FR-26.5 | 주소창은 자동완성 후보와 히스토리 제안을 제공해야 한다. | Should |
| FR-26.6 | breadcrumb 조각 우클릭/드롭다운으로 하위 폴더 빠른 이동을 제공할 수 있다. | Should |

**수용 기준**

- breadcrumb와 주소창은 같은 패널 경로 상태를 공유한다.
- 입력한 경로가 유효하지 않으면 현재 경로를 유지하고 오류를 표시한다.

## FR-27. 검색/필터 고도화

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-27.1 | 현재 폴더 파일명 필터는 1차 MVP에 포함한다. | Must |
| FR-27.2 | 재귀 파일명 검색을 제공할 수 있다. | Should |
| FR-27.3 | 파일 내용 검색을 제공할 수 있다. | Could |
| FR-27.4 | 검색 조건은 확장자, 크기, 수정일, 파일 종류를 조합할 수 있어야 한다. | Could |
| FR-27.5 | 검색 결과는 별도 가상 패널 또는 검색 결과 탭으로 표시할 수 있다. | Could |
| FR-27.6 | 검색 결과 항목에도 복사/이동/삭제/열기 등 기본 파일 작업을 적용할 수 있어야 한다. | Must if implemented |
| FR-27.7 | 필터 칩 UI(`*.rs`, 최근 7일, 100MB 이상 등)를 제공할 수 있다. | Could |

**수용 기준**

- 검색 결과가 현재 폴더 컨텍스트인지 재귀 검색 결과인지 명확히 표시된다.
- 검색 중 UI는 정지하지 않는다.
