# 01. 핵심 사용 경험: 시작, 패널, 목록, 탐색, 선택, 정렬/필터

## FR-1. 앱 시작과 초기 경로

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-1.1 | 앱은 실행 시 좌/우 패널을 초기 경로로 로드해야 한다. | Must |
| FR-1.2 | 시작 경로가 지정되면 좌/우 패널 모두 해당 경로에서 시작해야 한다. | Must |
| FR-1.3 | 시작 경로가 없으면 이전 종료 시점의 히스토리/상태를 복원해야 한다. | Should |
| FR-1.4 | 시작 경로가 유효하지 않으면 안전한 기본 경로 또는 직전 상태로 fallback해야 한다. | Must |
| FR-1.5 | 최근 작업 폴더 또는 홈 디렉토리를 빠르게 선택할 수 있는 시작 옵션을 제공할 수 있다. | Could |

**수용 기준**

- 유효한 디렉토리 경로로 실행하면 두 패널이 같은 경로를 표시한다.
- 유효하지 않은 경로는 오류로 앱을 종료하지 않는다.
- 상태 복원은 손상된 설정 파일을 만나도 앱 실행을 막지 않는다.

## FR-2. 메인 레이아웃과 패널

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-2.1 | 메인 화면은 상단 메뉴/도구 영역, 좌·우 파일 패널, 상태바, 명령/힌트 영역을 포함해야 한다. | Must |
| FR-2.2 | 좌·우 패널은 각각 독립적인 현재 경로, 선택 상태, 스크롤, 정렬, 필터, 히스토리를 가진다. | Must |
| FR-2.3 | 활성 패널은 테두리/헤더/강조 색 등으로 명확히 표시해야 한다. | Must |
| FR-2.4 | 창 크기에 따라 컬럼과 패널 표시를 반응형으로 조정해야 한다. | Must |
| FR-2.5 | 사용자는 듀얼 패널/단일 패널 보기를 전환할 수 있어야 한다. | Should |
| FR-2.6 | 사용자는 패널 비율을 50:50, 70:30, 30:70 등으로 조정할 수 있어야 한다. | Should |
| FR-2.7 | 너무 작은 창에서는 기능이 깨지지 않고 최소 창 크기 안내 또는 축약 UI를 제공해야 한다. | Must |
| FR-2.8 | 좌우 패널 사이 splitter를 마우스로 드래그해 폭을 조절할 수 있어야 한다. | Should |
| FR-2.9 | 현재 패널 상태를 잃지 않고 레이아웃 모드와 패널 비율을 변경해야 한다. | Must |

**수용 기준**

- 패널마다 경로 제목, 탭 개수, 파일 리스트, 스크롤 상태가 표시된다.
- 좁은 창에서도 파일명은 잘리고 앱이 패닉/크래시하지 않는다.
- 단일 패널 모드에서 `Tab` 또는 GUI 컨트롤로 좌/우 패널을 전환할 수 있다.

## FR-3. 파일/디렉토리 목록 표시

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-3.1 | 디렉토리 내용을 읽어 파일/디렉토리/심볼릭 링크/실행 파일을 구분해야 한다. | Must |
| FR-3.2 | 각 항목은 이름, 크기, 수정일, 생성일, 권한, 소유자/그룹 등 가능한 메타데이터를 표시할 수 있어야 한다. | Must |
| FR-3.3 | 디렉토리는 기본적으로 파일보다 먼저 표시해야 한다. | Must |
| FR-3.4 | 상위 디렉토리 이동 항목(`..`) 또는 동등한 GUI 탐색 컨트롤을 제공해야 한다. | Must |
| FR-3.5 | 숨김 파일 표시/숨김을 토글할 수 있어야 한다. | Must |
| FR-3.6 | 파일 타입별 아이콘과 색상을 제공해야 한다. | Must |
| FR-3.7 | 아이콘은 이모지/ASCII/플랫폼 네이티브 아이콘 중 선택 가능해야 한다. | Should |
| FR-3.8 | 큰 디렉토리에서도 스크롤이 부드럽고 리스트 렌더링이 지연되지 않아야 한다. | Must |
| FR-3.9 | 권한 부족·존재하지 않는 경로·깨진 심볼릭 링크 같은 오류는 항목 단위 또는 패널 단위로 명확히 표시해야 한다. | Must |
| FR-3.10 | 상세 목록, 간단 목록, 아이콘 보기, 썸네일 보기 같은 보기 모드를 지원할 수 있어야 한다. | Should |
| FR-3.11 | 이미지/동영상 파일의 썸네일은 백그라운드에서 생성하고 기본 탐색을 막지 않아야 한다. | Must if implemented |

**수용 기준**

- 파일 타입별 시각 구분이 가능하다.
- 숨김 파일 토글 시 양쪽 패널 또는 활성 패널 정책이 명확히 적용된다.
- 권한이 없는 폴더 진입 시 앱이 종료되지 않고 오류 메시지를 표시한다.

## FR-4. 탐색

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-4.1 | 위/아래 이동, 페이지 이동, 맨 위/맨 아래 이동을 지원해야 한다. | Must |
| FR-4.2 | 디렉토리 진입과 상위 디렉토리 이동을 지원해야 한다. | Must |
| FR-4.3 | 상위 디렉토리로 이동한 뒤 이전에 있던 하위 디렉토리에 포커스를 복원해야 한다. | Should |
| FR-4.4 | 패널 간 경로는 독립적으로 유지되어야 한다. | Must |
| FR-4.5 | 경로 직접 입력 이동을 지원해야 한다. | Must |
| FR-4.6 | 경로 입력은 파일 시스템 기반 자동완성과 히스토리 기반 제안을 제공해야 한다. | Should |
| FR-4.7 | 경로 입력은 `Tab` 자동완성, 후보 목록, 이전 단어 삭제 같은 편집 단축키를 지원해야 한다. | Should |
| FR-4.8 | 마운트 포인트/드라이브/홈 디렉토리 빠른 접근 UI를 제공해야 한다. | Must |
| FR-4.9 | GUI에서는 주소 표시줄, breadcrumb, 뒤로/앞으로 버튼, 새로고침 버튼을 제공해야 한다. | Must |
| FR-4.10 | 더블클릭 또는 `Enter`는 폴더 진입, 파일 열기, 압축 파일의 가상 디렉터리 진입처럼 타입별 기본 액션을 실행해야 한다. | Must |
| FR-4.11 | Breadcrumb의 각 경로 조각은 클릭 이동과 우클릭/드롭다운 하위 폴더 선택을 지원할 수 있다. | Should |

**수용 기준**

- `Enter`/더블클릭으로 디렉토리에 진입한다.
- `Backspace` 또는 상위 버튼으로 상위 폴더로 이동한다.
- 경로 입력창에 일부 경로를 입력하면 후보 목록이 표시된다.

## FR-5. 선택

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-5.1 | 현재 커서/포커스 항목의 단일 선택을 지원해야 한다. | Must |
| FR-5.2 | 다중 선택 토글을 지원해야 한다. | Must |
| FR-5.3 | 전체 선택, 선택 반전, 전체 해제를 지원해야 한다. | Must |
| FR-5.4 | 선택된 항목은 일반 포커스와 구분되는 마커/색상/체크박스로 표시해야 한다. | Must |
| FR-5.5 | 선택 개수와 선택 총 크기를 상태바에 표시해야 한다. | Must |
| FR-5.6 | 디렉토리 변경 시 기존 선택 상태는 안전하게 초기화되어야 한다. | Must |
| FR-5.7 | `..` 또는 상위 이동용 가상 항목은 파일 작업 대상으로 선택되지 않아야 한다. | Must |
| FR-5.8 | Shift 클릭 범위 선택을 지원해야 한다. | Must |
| FR-5.9 | Cmd/Ctrl 클릭 개별 다중 선택을 지원해야 한다. | Must |
| FR-5.10 | 마우스 드래그 박스 선택 또는 리스트 드래그 선택을 지원할 수 있다. | Should |
| FR-5.11 | 키보드 선택과 마우스 선택은 같은 선택 모델을 공유해야 한다. | Must |

**수용 기준**

- 선택된 여러 파일에 복사/이동/삭제/압축 작업이 적용된다.
- 선택 상태와 현재 포커스가 시각적으로 혼동되지 않는다.
- Shift/Cmd/Ctrl 클릭 이후에도 단축키 파일 작업이 같은 선택 대상에 적용된다.

## FR-6. 정렬과 필터

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-6.1 | 이름, 크기, 수정일, 확장자 기준 정렬을 지원해야 한다. | Must |
| FR-6.2 | 오름차순/내림차순 정렬을 지원해야 한다. | Must |
| FR-6.3 | 정렬 상태는 컬럼 헤더 또는 상태바에 표시되어야 한다. | Must |
| FR-6.4 | 디렉토리 우선 정렬 정책을 제공해야 한다. | Must |
| FR-6.5 | 파일명 필터를 제공해야 한다. | Must |
| FR-6.6 | 필터는 부분 문자열과 글로브 패턴(`*`, `?`)을 지원해야 한다. | Must |
| FR-6.7 | 필터 입력 중 라이브 적용과 매칭 하이라이트를 제공해야 한다. | Should |
| FR-6.8 | 컬럼 헤더 클릭으로 정렬 기준과 방향을 변경할 수 있어야 한다. | Must |
| FR-6.9 | 필터는 검색 바, 단축키, 메뉴에서 모두 접근할 수 있어야 한다. | Should |

**수용 기준**

- 컬럼 헤더 클릭 또는 단축키로 정렬 기준이 바뀐다.
- `*.rs` 같은 패턴 필터가 파일 목록에 적용된다.
- 필터 해제 시 전체 목록이 복원된다.
