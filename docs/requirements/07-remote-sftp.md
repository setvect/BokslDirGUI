# 07. 원격 파일 관리: SFTP

- 상태: 확정(2026-10-31, 사용자 요청으로 7절 제안안 채택), 구현 완료(2026-10-31, 브랜치 `claude/sftp-remote-20261031`), macOS·Windows VM E2E 완료(2026-10-31), 결과는 10절
- 작성일: 2026-10-31
- 목적: 듀얼 패널 한쪽 또는 양쪽을 SFTP 서버 디렉터리로 열어 로컬과 같은 키보드 중심 조작으로 탐색·전송·관리
- 구현 기준: 7절 결정 사항, 8절 시험 계획, 구현 설계 문서에 명령·액션·상태 반영

## 1. 범위와 근거

### 1.1 범위

- 대상: SFTP(SSH File Transfer Protocol 버전 3, OpenSSH 서버 기준)
- 위치: 기존 TUI 기능 동등성 범위 밖의 GUI 확장 기능
- 우선순위 표기: 기존 요구사항과 같은 Must·Should·Could, SFTP 기능 안의 상대 중요도 의미(축소 범위 의미 아님)
- 범위 밖, 별도 결정: FTP·FTPS, SMB, WebDAV, 클라우드 저장소, SCP 단독 전송
- 확장 전제: 원격 경로 체계와 연결 계층을 프로토콜 추가가 가능한 구조로 설계

### 1.2 근거

- 기존 TUI: 코드 구현 없음, `BokslDir/docs/Architecture.md` 11.2 "원격 파일 시스템(미래)"에 SFTP/FTP·클라우드·`FileSystem` 추상화 구상만 존재
- 현재 GUI: 원격 접근 요구사항·명령·액션 없음
- 재사용 가능한 기존 구조

| 기존 구조 | 위치 | SFTP 적용 |
| --- | --- | --- |
| 압축 내부 가상 경로 `archive.zip:/inner` | `src/ui/archiveVirtual.ts` | 원격 경로 `sftp://user@host:port/path`의 표기·판정 선례 |
| 패널 데이터 소스(`listDir`·`gotoPath`·감시) | `src/ui/panelDataSource.ts` | 원격 목록·이동을 같은 패널 상태 흐름으로 연결 |
| 장기 작업 공통 시작·진행·충돌·취소 | `src-tauri/src/operation/runtime.rs` | 업로드·다운로드·원격 삭제를 같은 작업 상태 기계로 실행 |
| 액션 속성(`platformFeature`·`shortcutPlatforms`) | `src/actions/registry.ts` | 원격 지원 여부를 액션 속성으로 표시 |
| 경로 이동 입력 `~`·상대 경로(FR-26.4) | `src-tauri/src/navigation.rs` | 원격 패널에서는 원격 홈·현재 원격 폴더 기준 해석 |
| 민감 정보 비기록(FR-23.5), 압축 암호 처리 | `docs/implementation/tauri-command-api.md` | 접속 암호·키 암호를 설정·이벤트·로그·오류 상세에서 제외 |

## 2. 설계 원칙

- 원격 패널도 로컬 패널과 같은 키·메뉴·컨텍스트 메뉴·드래그·클립보드 경로 사용, 공통 action registry 필수
- 연결·인증·전송·원격 파일 변경은 Rust command/service 계층에서 검증·실행
- 업로드·다운로드·원격 삭제는 기존 작업 상태(진행률·충돌·취소·오류 요약) 재사용, 별도 진행 UI 생성 금지
- 원격 지연과 연결 끊김을 일상 상황으로 취급: 모든 원격 요청 비동기·시간 제한·취소 가능
- 호스트 키 검증 필수: 처음 접속 시 지문 확인, 바뀐 키는 연결 차단
- 비밀 정보(접속 암호·키 암호)는 OS 자격 증명 저장소에만 저장, 설정 파일·패널 경로·이벤트·로그·오류 상세 기록 금지
- 원격에는 휴지통이 없으므로 원격 삭제는 영구 삭제 확인 흐름만 허용

## 3. 기능 요구사항

### FR-34. 연결과 사이트 관리

| ID | 요구사항 | 우선순위 |

| FR-34.3 | 사이트 목록 제공: 이름·호스트·포트·사용자·인증 방식·원격 시작 경로 저장, 추가·편집·복제·삭제 | Must |

| FR-34.5 | 패널 머리글에 연결 표시(사이트 이름·사용자·호스트·상태), 색 외에 글자로도 구분 | Must |
| FR-34.6 | 연결 해제: 활성 패널의 원격 연결 종료, 연결 전 로컬 경로로 복귀 | Must |
| FR-34.7 | 끊긴 연결의 명시적 상태 표시와 재연결 동작 제공 | Must |

| FR-34.9 | `~/.ssh/config`의 `Host` 항목 가져오기(`HostName`·`User`·`Port`·`IdentityFile`), 지원하지 않는 항목은 경고 | Should |
| FR-34.10 | 연결 유지 간격(keepalive)과 연결 시간 제한 설정 | Should |
| FR-34.11 | 두 패널을 서로 다른 서버에 연결, 서버 간 전송 | Could |
| FR-34.12 | 점프 호스트(`ProxyJump`) 경유 연결 | Could |

**수용 기준**

- 사이트 목록에서 Enter 한 번으로 연결, 연결 중 진행 표시와 취소 가능
- 설정 파일과 세션 정보에 접속 암호·키 암호 문자열 없음
- 연결이 끊긴 패널에서는 파일 작업 비활성, 재연결·연결 해제만 활성

### FR-35. 인증과 보안

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-35.1 | 암호 인증, 저장 선택 시 OS 자격 증명 저장소 사용(macOS 키체인, Windows 자격 증명 관리자) | Must |
| FR-35.2 | 공개 키 인증: OpenSSH 개인 키 파일(Ed25519·ECDSA·RSA), 경로를 비우면 `~/.ssh` 기본 키를 OpenSSH 순서로 시도, 키 암호 입력과 저장 선택 | Must |
| FR-35.3 | 처음 접속하는 서버의 호스트 키 지문(SHA-256)과 알고리즘 표시, 신뢰 확인 후 저장 | Must |
| FR-35.4 | 저장된 호스트 키와 다르면 연결 차단, 변경 사실과 두 지문 표시 | Must |
| FR-35.5 | 접속 암호·키 암호를 설정·패널 경로·이벤트·로그·오류 상세·작업 요약에 기록 금지 | Must |
| FR-35.6 | 사이트 삭제 시 저장된 자격 증명 함께 삭제, 저장된 자격 증명만 따로 삭제 가능 | Must |
| FR-35.7 | SSH 에이전트 인증(macOS `SSH_AUTH_SOCK`, Windows OpenSSH 에이전트) | Should |
| FR-35.8 | keyboard-interactive 인증(2단계 인증 코드 입력) | Should |
| FR-35.9 | 기존 `~/.ssh/known_hosts`의 신뢰 정보 읽기, 새 신뢰 정보는 앱 전용 파일에 기록 | Should |

**수용 기준**

- 호스트 키 확인 창에서 취소하면 어떤 원격 요청도 실행되지 않음
- 호스트 키 불일치는 "그래도 연결" 기본 선택지 없이 차단
- 비밀 정보 비노출은 직렬화·로그 출력 대상 테스트로 확인

- 한글·공백·특수 문자 이름의 원격 항목을 로컬과 같은 표기로 표시
- 원격 목록 요청 중에도 반대 패널 조작과 키 입력 응답 유지
- 늦게 도착한 이전 원격 목록 응답은 현재 패널 상태를 덮어쓰지 않음

## 4. 화면과 조작

### 4.1 메뉴와 액션

- 새 최상위 메뉴 "원격(R)" 제안, `R` 가속 키는 현재 미사용

| 액션 ID 후보 | 메뉴 항목 | 단축키 후보 | 비고 |
| --- | --- | --- | --- |
| `remote.sites` | 사이트 목록… | `g r` | 연결·편집·삭제 진입점 |
| `remote.connect` | 새 연결… | 없음 | 저장 없이 한 번 연결 |
| `remote.disconnect` | 연결 해제 | `g d` | 원격 패널에서만 활성 |

- 원격 패널 빈 영역 메뉴: 새로고침, 경로 이동, 새 폴더, 붙여넣기(업로드), 연결 정보, 연결 해제

### 4.2 원격 패널에서의 기존 액션

| 구분 | 액션 | 원격 패널 동작 |
| --- | --- | --- |
| 그대로 지원 | 탐색·정렬·필터·숨김·선택·탭·히스토리·경로 이동·새로고침 | 원격 목록에 같은 규칙 적용 |
| 그대로 지원 | 복사·이동·새 폴더·이름 변경·다중 이름 변경·파일 정보 | 원격 서비스로 실행 |
| 의미 변경 | 삭제(`d`) | 휴지통 없음 → 영구 삭제 확인 흐름 |
| 받은 뒤 실행 | 빠른 보기, 기본 앱으로 열기 | 임시 위치로 받은 뒤 실행 |
| 비활성 | 휴지통 되돌리기, Finder·탐색기에서 보기, 현재 폴더를 파일 관리자·터미널에서 열기, 다음으로 열기 | 로컬 전용 |

- 구현 방식: 7단계의 액션 속성 선례에 따라 액션별 원격 지원 여부 속성(예: `remoteSupport`) 추가, `isActionAvailable`이 판정

### 4.3 화면 요소

- 연결 창: 사이트 이름, 호스트, 포트, 사용자, 인증 방식(암호·키 파일·에이전트), 개인 키 경로(비우면 기본 키), 원격 시작 경로, 자격 증명 저장 선택
- 호스트 키 확인 창: 호스트·포트, 키 알고리즘, SHA-256 지문, "신뢰하고 연결"·"취소", 기본 포커스는 취소
- 사이트 목록: 항목마다 이름(첫 줄)과 `사용자@호스트 · 인증 방식`(둘째 줄)
  - 버튼 두 줄: 목록 아래 사이트 관리(새 사이트·편집·복제·삭제·저장된 암호 삭제), 구분선 아래 "SSH 설정 가져오기"(왼쪽)와 닫기·연결(오른쪽)
  - 키: 위·아래로 선택, `Enter`로 연결, `Delete`·`Backspace`로 삭제 확인 창
  - 고른 사이트가 목록 밖이면 창을 열 때와 키로 옮길 때 스크롤
- 사이트 삭제 확인 창: 지울 사이트, 저장된 암호·키 암호가 있으면 함께 삭제 안내, "취소"·"삭제", 기본 포커스는 취소, 취소·`Esc`는 같은 사이트를 고른 목록으로 복귀
- 패널 머리글: `SFTP · 사이트 이름` 표시와 연결 상태 문구(연결 중·연결됨·다시 연결 중·끊김)
- 위치 목록(`g m`): 저장된 사이트 묶음 추가

## 5. 구조

### 5.1 경로 표기

- 원격 패널 경로: `sftp://사용자@호스트:포트/절대/경로`
- 사용자·경로의 예약 문자(`@`·`:`·`/`·`%`)는 퍼센트 인코딩, 표시는 디코딩한 이름
- 원격 경로 안의 구분자는 항상 `/`, Windows 앱에서도 같음
- 프론트 판정·파서: `archiveVirtual.ts` 선례를 따른 원격 경로 모듈, 압축 가상 경로와 중첩하지 않음

### 5.2 계층 경계

- 프론트: 패널 데이터 소스가 경로 체계로 로컬·원격 목록 요청 분기, 액션 문맥에 원격 경로 여부 추가
- Rust 연결 관리자: 사이트별 SSH 연결 하나, 목록·작업마다 SFTP 채널 분리(긴 전송이 목록 요청을 막지 않도록)
- Rust 원격 서비스: 목록·정보·새 폴더·이름 변경, 장기 작업은 기존 `launch_operation`으로 실행
- 작업 명령: 기존 `start_copy`·`start_move`·`start_delete`가 출발·대상 경로 체계로 로컬·원격 처리 분기(메뉴·키보드·드래그·클립보드 공통 실행 경로 유지)
- 단일 활성 작업 정책: 현재 백엔드 차단 유지, 원격 전송 대기열은 별도 결정

### 5.3 명령·이벤트 후보

| 이름 | 입력 | 출력 | 비고 |
| --- | --- | --- | --- |
| `remote_connect` | `{ siteId?, host, port, user, auth, startPath? }` | `RemoteSession` | 신뢰 전 호스트 키면 지문을 담은 `host_key_unknown` 오류 |
| `remote_trust_host_key` | `{ host, port, algorithm, fingerprint }` | `void` | 앱 전용 known_hosts에 기록 |
| `remote_disconnect` | `{ sessionId }` | `void` | 진행 중 작업이 있으면 거절 |
| `remote_store_secret`·`remote_forget_secret` | `{ siteId, kind }` | `void` | OS 자격 증명 저장소 |
| `list_dir`·`goto_path`·`get_metadata`·`preview_file` | 기존 입력 | 기존 DTO | 경로가 `sftp://`면 원격 처리 |
| `create_dir`·`rename_entry` | 기존 입력 | 기존 DTO | 원격 경로 지원 |
| `start_copy`·`start_move`·`start_delete` | 기존 입력 | `OperationStarted` | 원격 삭제는 영구 삭제만 |
| 이벤트 `remote_connection_changed` | `{ sessionId, state, error? }` | - | `EVENTS`·Rust 상수 대조 대상 |

### 5.4 저장 형식

- 설정 `remoteSites`: `{ id, name, host, port, user, authMethod, keyPath?, startPath?, savedSecret }` 선택 필드 추가, 기존 설정 파일과 호환
- 자격 증명: OS 자격 증명 저장소 서비스 이름 `BokslDirGUI`, 계정 `sftp:<siteId>:<password|passphrase>`
- 호스트 키: 설정 폴더의 앱 전용 `known_hosts`(OpenSSH 형식)

## 6. 라이브러리 선택지

| 후보 | 방식 | 장점 | 주의 |

- 도입 전 확인: Windows OpenSSH 에이전트 연결 지원, 키 형식(OpenSSH·PEM) 지원 범위, 라이선스 고지 반영

### 8.2 VM E2E

- 서버: Tart macOS VM의 원격 로그인(SSH)을 SFTP 서버로 사용
  - 2026-10-31 확인: Windows VM에서 Tart VM 22번 포트 연결 성공, Tart VM 관리자 계정의 비밀번호 없는 `sudo`와 `pfctl`·`dnctl` 사용 가능
- 앱 구성: macOS 앱은 같은 VM의 SSH 서버, Windows 앱은 네트워크 경유로 Tart VM SSH 서버 접속
- 조작 도구: macOS는 `vmkey`·`vmdrag`([VM E2E 입력 도구](../../scripts/vm-e2e/README.md)), Windows는 VirtualBox 마우스·키 입력과 ISO 전달·게스트 속성 보고

| 상황 | 만드는 방법 |
| --- | --- |
| 전송 중 끊김 | 서버 VM에서 `pfctl`로 22번 포트 차단 |
| 높은 지연·패킷 손실 | `dnctl`(dummynet)로 100ms 지연·1% 손실 |
| 호스트 키 변경 | 서버 호스트 키 재생성 후 재접속, 차단 확인 |
| 권한 거부·용량 부족 | 읽기 전용 폴더, 작은 디스크 이미지 |
| 대용량 | 1GB 파일, 5만 항목 폴더 |

- 시나리오: 연결·사이트 저장·재시작 후 복원, 한글·공백 이름, 1GB 진행률·취소·이어받기, 패널 간·같은 패널 끌어 놓기, Finder·탐색기 드롭 업로드, 원격 영구 삭제
- 증거: 화면 캡처, 서버 쪽 SSH 목록·sha256 대조, Windows 게스트 속성 보고, 결과는 검토 문서에 기록

### 8.3 보안·성능 점검

- 비밀 정보 흔적: 고유 시험 암호로 접속 후 설정 파일·임시 폴더·앱 출력 검색 0건, 저장 선택 시 키체인·Windows 자격 증명 관리자에만 존재
- 전송 속도: 요청 겹쳐 보내기(파이프라이닝) 여부가 핵심 위험, 100ms 지연 조건에서 같은 서버의 `sftp` 명령과 속도 비교
- 대형 목록: 5만 항목 원격 폴더의 첫 화면 표시 시간 측정

### 8.4 사용자 확인 필요

- macOS 키체인 첫 접근 허용 창: 보안 창이라 VM 창에서 사용자 허용
- Windows 서명 없는 설치본: 스마트 앱 컨트롤 차단 가능, 차단 시 해당 빌드의 Windows 화면 확인 누락으로 기록
- 호스트 Mac의 원격 로그인 설정 변경 없음, VM만 서버로 사용

### 10.2 설계 결정과 차이

- 키 파일: 승인된 라이브러리(6절)에 파일 선택 플러그인이 없어 경로 입력
- 개인 키 경로를 비운 경우: 터미널 `ssh`처럼 `~/.ssh`의 `id_rsa`·`id_ecdsa`·`id_ed25519`를 차례로 시도(2026-10-31)
  - 하드웨어 보안 키(`_sk`)·지원이 끝난 DSA 제외, 읽지 못하거나 키 암호가 맞지 않는 키는 건너뜀
  - 하나도 보내지 못하면 키 암호 필요를 우선 안내, 기본 키가 없으면 경로 입력 안내
  - 이전의 고정 기본값(`~/.ssh/id_ed25519` 미리 채움) 대체, 경로를 적은 기존 사이트는 그 파일만 사용
- 공개 키(`.pub`)를 개인 키 자리에 넣은 경우: 연결 창에서 연결 전에, 백엔드는 키 읽기 실패 때 짝이 되는 개인 키 안내
- 원격 패널의 `/` 입력: 원격 절대 경로로 해석, 로컬 이동은 Windows 드라이브·UNC 경로나 위치 목록 사용
- 원격 압축 파일: 압축 가상 경로로 해석하지 않음(`sftp://u@example.zip:22/`의 포트 오인 방지 포함)
- 대소문자만 바꾸는 원격 이름 변경: 같은 항목이면 임시 이름 경유
- 권한 변경 재귀 적용: 선택 항목도 범위로 거름(파일만 바꿀 때 선택 폴더 실행 권한 손실 방지)
- 끊김 임시본 이어받기: 길이만 믿지 않고 표본 대조, 시험에서 빈 구간 임시본 재현 후 반영
- 정확한 위치 이동: 위치 목록·연결 해제 복귀는 패널 기준 없이 해석, 사용자가 입력한 경로만 현재 패널 기준(VM E2E 결함 수정)
- 비밀값 저장: 그 값으로 새로 인증한 연결에서만 저장, 같은 계정·주소의 기존 연결을 재사용하면 저장하지 않고 이유 안내
- 같은 계정·주소의 여러 사이트: 연결 하나를 공유, 머리글은 처음 맞는 사이트 이름 표시
- 연결 해제: 파일 작업이 진행 중이면 화면에서 연결 해제 비활성(작업이 어느 연결을 쓰는지와 무관하게 일괄 적용, 2026-10-31)
- 백엔드 `remote_disconnect`: 5.3 후보의 거절 조건 미구현, 화면의 비활성 판정이 유일한 보호, 계약은 [`tauri-command-api.md`](../implementation/tauri-command-api.md)
- 사이트 삭제 확인: 같은 자리의 "삭제" 버튼이 "삭제 확인"으로 바뀌던 두 번 누르기 대신 별도 확인 창(2026-10-31)
  - 이전 방식의 문제: 지울 사이트와 함께 지워지는 저장된 비밀값 안내 없음, 위험 버튼 색 미적용(`.filter-actions`에 `danger` 규칙 없음), 버튼 폭 변화로 다른 버튼 위치 이동
  - 확인 창은 연결 흐름의 한 단계(`deleteSite`), 창을 겹치지 않고 사이트 목록과 교대
  - 삭제 뒤 선택: 지운 자리의 다음 사이트, 마지막이었으면 새 마지막 사이트(이전에는 항상 첫 사이트)
- 사이트 목록 버튼 배치: 역할별 두 줄 고정, 창 폭 620px에서 680px로 확대(2026-10-31)
  - 근거: 버튼 8개 한 줄 폭(한국어 683px·영어 973px)이 창 안쪽 폭(594px)을 넘어 넘친 버튼이 임의 위치에서 줄바꿈
  - 확대 근거: 영어 사이트 관리 줄 604px(macOS 앱의 SF Mono 글자 폭으로 환산하면 약 617px), 한국어는 406px
  - 측정: macOS 브라우저 미리보기의 실제 대화상자, 글꼴 16px, 환산값은 추정치

### 10.4 macOS VM E2E

- 기준일: 2026-10-31, 증거 화면은 `temp/verification/sftp-e2e-20261031/`(저장소 제외 폴더)

| 사이트 저장·재시작 복원 | 통과 | 설정 파일에 비밀값 없음, 재시작 때 입력 없이 재연결해 원격 탭 복원 |
| 키 암호 저장(키체인) | 통과(수정 후) | 키체인 항목 생성, 허용 창 없음, 이후 입력 없이 연결, 설정 파일에서 키 암호 검색 0건 |
| 기존 연결 재사용 시 비밀값 저장 | 통과(수정 후) | 틀린 키 암호를 입력해도 저장하지 않고 이유 안내, 키체인 항목 없음 |
| SSH 설정 가져오기 | 통과 | 1개 추가, 같은 계정·주소 항목 건너뜀, `ServerAliveInterval` 경고 |
| 연결 해제 복귀(FR-34.6)·위치 목록 이동 | 통과(수정 후) | 연결 해제 뒤 로컬 홈, 원격 패널에서 고른 위치 목록 항목은 로컬로 이동 |
| 연결되지 않은 `sftp://` 주소 이동(FR-36.3) | 통과 | 사이트 값이 채워진 연결 창 뒤 요청 주소로 이동 |

- 미실시: 1GB 전송(300MB로 대신), 5만 항목 목록 측정, 100ms 지연·1% 손실, 권한 거부·용량 부족, Finder 드롭 업로드, 에이전트·keyboard-interactive 인증
- 키체인 첫 접근 허용 창: 이번 빌드에서는 나타나지 않음(앱이 만든 항목을 같은 앱이 읽음)
