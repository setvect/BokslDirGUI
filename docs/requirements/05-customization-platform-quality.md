# 05. 커스터마이징, 플랫폼, 품질: 테마, i18n, 설정, 보안, 성능

## FR-19. 테마와 표시 설정

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-19.1 | Dark, Light, High Contrast 테마를 제공해야 한다. | Must |
| FR-19.2 | 런타임 테마 전환을 지원해야 한다. | Must |
| FR-19.3 | 선택한 테마는 재시작 후 복원되어야 한다. | Must |
| FR-19.4 | 커스텀 테마 파일 또는 GUI 테마 편집은 후속 기능으로 검토한다. | Could |
| FR-19.5 | 파일 크기 표시는 자동 단위와 바이트 표시를 전환할 수 있어야 한다. | Should |
| FR-19.6 | 아이콘 표시 방식은 호환성 문제를 고려해 전환 가능해야 한다. | Should |
| FR-19.7 | 고대비 모드는 접근성 요구사항으로 취급해야 한다. | Must |
| FR-19.8 | 보기 모드, 미리보기 패널 표시 여부, 사이드바 표시 여부를 저장할 수 있어야 한다. | Should |

**수용 기준**

- 테마 전환 즉시 전체 UI에 적용된다.
- 앱 재시작 후 마지막 테마가 유지된다.

## FR-20. 언어와 한글/Unicode

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-20.1 | 한국어와 영어 UI를 지원해야 한다. | Must |
| FR-20.2 | 런타임 언어 전환을 지원해야 한다. | Must |
| FR-20.3 | 선택 언어는 재시작 후 복원되어야 한다. | Must |
| FR-20.4 | 사용자 노출 문자열은 렌더링 코드에 하드코딩하지 않고 i18n 키를 통해 관리해야 한다. | Must |
| FR-20.5 | 한글 파일명, CJK 문자, 이모지, 결합 문자를 포함한 파일명이 깨지지 않게 표시되어야 한다. | Must |
| FR-20.6 | 모든 입력창은 UTF-8 문자 단위 커서 이동/삭제를 정확히 처리해야 한다. | Must |
| FR-20.7 | GUI에서는 기존 터미널 IME 경고 대신 네이티브 입력기 동작을 자연스럽게 지원해야 한다. | Must |
| FR-20.8 | 정렬/검색/필터는 Unicode 대소문자와 조합 문자 처리를 고려해야 한다. | Should |

**수용 기준**

- 한글 파일명을 가진 항목이 잘림/선택/정렬/이름 변경 과정에서 깨지지 않는다.
- 한국어 UI로 전환하면 메뉴, 다이얼로그, 상태바, 도움말이 함께 변경된다.

## FR-21. 설정과 상태 저장

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-21.1 | 테마, 언어, 히스토리, 북마크를 저장해야 한다. | Must |
| FR-21.2 | 설정 파일은 앱 전용 설정 경로에 저장해야 한다. | Must |
| FR-21.3 | 설정 스키마 버전을 두고 호환되지 않는 설정은 안전하게 무시해야 한다. | Should |
| FR-21.4 | 설정 저장 실패가 앱 사용을 막지 않아야 한다. | Should |
| FR-21.5 | GUI에서는 설정 화면을 제공해 테마/언어/편집기/단축키 등을 변경할 수 있어야 한다. | Should |
| FR-21.6 | 창 크기, 패널 비율, 사이드바/미리보기 표시 여부를 저장할 수 있어야 한다. | Should |
| FR-21.7 | 설정 저장은 원자적 쓰기를 고려해야 한다. | Should |

**수용 기준**

- 앱 종료 시 상태 저장을 시도하고, 다음 실행 시 복원된다.
- 설정 파일이 손상되어도 앱은 기본값으로 시작한다.

## FR-22. 알림, 토스트, 다이얼로그

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-22.1 | 정보/오류/확인/선택/입력/진행률 다이얼로그를 제공해야 한다. | Must |
| FR-22.2 | 짧은 성공 메시지는 토스트/스낵바로 표시해야 한다. | Must |
| FR-22.3 | 위험 작업은 모달 확인을 사용해야 한다. | Must |
| FR-22.4 | 오류 메시지는 작업명, 대상 경로, 원인, 힌트를 포함해야 한다. | Should |
| FR-22.5 | 다이얼로그는 키보드와 마우스로 모두 조작 가능해야 한다. | Must |
| FR-22.6 | 마스킹 입력이 필요한 암호 입력은 일반 텍스트와 구분해야 한다. | Must |
| FR-22.7 | 장시간 작업 완료는 토스트와 선택적 시스템 알림을 제공할 수 있다. | Should |
| FR-22.8 | 시스템 알림은 사용자가 비활성화할 수 있어야 한다. | Should |

**수용 기준**

- 다이얼로그에서 `Esc`는 취소/닫기로 동작한다.
- 암호 입력 필드는 화면에 원문을 표시하지 않는다.

## FR-23. 보안과 데이터 보호

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-23.1 | 파일 작업은 사용자가 명시적으로 선택한 경로와 항목에 대해서만 수행해야 한다. | Must |
| FR-23.2 | 압축 해제는 대상 디렉토리 밖으로 파일이 쓰이지 않도록 경로를 정규화/검증해야 한다. | Must |
| FR-23.3 | 외부 명령 실행 기능은 기본 비활성 또는 명확한 사용자 확인을 거쳐야 한다. | Should |
| FR-23.4 | 영구 삭제와 덮어쓰기는 되돌릴 수 없음을 명확히 안내해야 한다. | Must |
| FR-23.5 | 작업 로그에 암호 같은 민감 정보를 남기지 않아야 한다. | Must |
| FR-23.6 | GUI 프레임워크가 웹뷰 기반일 경우 파일 시스템 API는 최소 권한으로 노출해야 한다. | Must |
| FR-23.7 | 드래그 앤 드롭으로 들어온 외부 경로도 일반 파일 작업과 같은 검증을 거쳐야 한다. | Must if implemented |
| FR-23.8 | 미리보기는 실행 가능한 콘텐츠를 자동 실행하지 않아야 한다. | Must if implemented |

## FR-24. 플랫폼 호환성

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-24.1 | macOS, Windows, Linux 데스크톱을 목표로 설계해야 한다. | Must |
| FR-24.2 | OS 기본 앱 열기, 휴지통, 권한, 실행 파일 판별, 드라이브/마운트 표시를 플랫폼별로 처리해야 한다. | Must |
| FR-24.3 | macOS에서는 `/Volumes`, Linux에서는 `/mnt`, `/media`, Windows에서는 드라이브 목록을 빠른 접근에 반영해야 한다. | Should |
| FR-24.4 | 파일 경로 구분자, 대소문자 민감도, 예약어/불가 문자 차이를 고려해야 한다. | Must |
| FR-24.5 | 심볼릭 링크/바로가기/alias 처리는 플랫폼별 정책을 문서화해야 한다. | Should |
| FR-24.6 | OS별 파일 드래그 앤 드롭, reveal, 기본 앱 열기, 휴지통 기능을 별도 테스트해야 한다. | Must |

## NFR-1. 성능

| ID | 요구사항 | 목표 |
| --- | --- | --- |
| NFR-1.1 | 큰 디렉토리 로딩 | 10,000개 항목에서도 UI가 정지하지 않을 것 |
| NFR-1.2 | 입력 반응성 | 일반 키/마우스 조작 지연이 체감되지 않을 것 |
| NFR-1.3 | 장시간 작업 | 파일 복사/이동/삭제/압축 중에도 탐색 UI 또는 최소 취소 UI가 반응할 것 |
| NFR-1.4 | 리스트 렌더링 | 가상 스크롤/부분 렌더링 등으로 대량 항목을 처리할 것 |
| NFR-1.5 | 메타데이터 계산 | 디렉토리 크기 계산은 백그라운드 또는 명시 요청 기반으로 수행할 것 |
| NFR-1.6 | 썸네일/미리보기 | 백그라운드 생성과 캐시를 사용하고 기본 탐색을 막지 않을 것 |

## NFR-2. 안정성

| ID | 요구사항 |
| --- | --- |
| NFR-2.1 | 모든 I/O 오류는 앱 크래시가 아닌 사용자 메시지로 처리해야 한다. |
| NFR-2.2 | 작업 중 일부 실패가 전체 앱 상태를 손상시키지 않아야 한다. |
| NFR-2.3 | 작업 완료/취소/실패 후 임시 파일과 임시 디렉토리를 정리해야 한다. |
| NFR-2.4 | 앱 강제 종료 후에도 설정 파일이 손상되지 않도록 원자적 저장 방식을 고려해야 한다. |
| NFR-2.5 | 테스트 가능한 파일 작업 계층을 두어 실제 파일 시스템 회귀를 줄여야 한다. |
| NFR-2.6 | 작업 큐가 있으면 앱 종료 시 진행 중 작업 처리 정책을 명확히 해야 한다. |

## NFR-3. 접근성/사용성

| ID | 요구사항 |
| --- | --- |
| NFR-3.1 | 고대비 테마를 제공해야 한다. |
| NFR-3.2 | 모든 주요 기능은 키보드만으로 접근 가능해야 한다. |
| NFR-3.3 | 상태 변화는 색상만이 아니라 텍스트/아이콘/마커로도 구분 가능해야 한다. |
| NFR-3.4 | 오류 메시지는 사용자가 다음 행동을 알 수 있게 작성해야 한다. |
| NFR-3.5 | 한글 UI와 한글 파일명을 1급 사용 시나리오로 검증해야 한다. |
| NFR-3.6 | 마우스 전용 기능은 키보드 대체 경로를 제공해야 한다. |
