# 02. 파일 작업: 복사, 이동, 삭제, 속성, 압축, 외부 앱

## FR-7. 파일 복사/이동

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-7.1 | 단일 파일, 다중 파일, 디렉토리 재귀 복사를 지원해야 한다. | Must |
| FR-7.2 | 단일 파일, 다중 파일, 디렉토리 이동을 지원해야 한다. | Must |
| FR-7.3 | 이동은 가능한 경우 빠른 rename을 사용하고, 불가능하면 복사 후 원본 삭제 방식으로 처리해야 한다. | Must |
| FR-7.4 | 대상 경로는 반대 패널 경로를 기본값으로 제안해야 한다. | Should |
| FR-7.5 | 사용자는 대상 경로를 직접 입력하거나 GUI 폴더 선택기로 지정할 수 있어야 한다. | Must |
| FR-7.6 | 작업 전 전체 파일 수와 총 바이트를 계산해 진행률에 반영해야 한다. | Must |
| FR-7.7 | 자기 자신 내부로 복사/이동 같은 위험한 경로는 차단해야 한다. | Must |
| FR-7.8 | 심볼릭 링크 처리 정책을 명확히 해야 한다. 디렉토리 symlink 복사/이동 미지원 시 사용자에게 설명해야 한다. | Must |
| FR-7.9 | 패널 간 드래그 앤 드롭으로 복사/이동을 시작할 수 있어야 한다. | Should |
| FR-7.10 | 드래그 작업은 기본 동작(복사/이동)과 보조키 기반 동작 전환을 명확히 표시해야 한다. | Should |
| FR-7.11 | Cmd+C로 선택/포커스 항목을 복사 준비하고 Cmd+V로 활성 패널 현재 폴더에 붙여넣어야 한다. 기존 y/F5 반대 패널 즉시 복사는 유지한다. | Must |

**수용 기준**

- 파일 충돌 없는 복사/이동은 완료 후 대상 패널에 결과가 나타난다.
- 권한 오류·디스크 공간 부족·중복 이름 오류가 사용자에게 표시된다.
- 작업 완료 후 선택 상태가 초기화된다.

## FR-8. 충돌 처리와 진행률

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-8.1 | 대상 파일/폴더가 이미 존재하면 충돌 다이얼로그를 표시해야 한다. | Must |
| FR-8.2 | 충돌 다이얼로그는 덮어쓰기, 건너뛰기, 모두 덮어쓰기, 모두 건너뛰기, 취소를 제공해야 한다. | Must |
| FR-8.3 | 진행률 UI는 현재 파일, 전체/완료 파일 수, 전체/처리 바이트, 백분율, 속도, ETA를 표시해야 한다. | Must |
| FR-8.4 | 작업 중 취소를 지원해야 한다. | Must |
| FR-8.5 | 일부 실패가 발생해도 가능한 작업을 계속하고 마지막에 오류 요약을 제공해야 한다. | Should |
| FR-8.6 | 오류 요약은 전체 실패 수와 대표 오류를 보여주고 상세 로그 접근을 제공해야 한다. | Should |
| FR-8.7 | 충돌 UI는 원본/대상 파일의 크기, 수정일, 경로를 비교 표시해야 한다. | Should |
| FR-8.8 | 충돌 시 새 이름으로 보관 또는 자동 rename 옵션을 제공할 수 있다. | Could |

**수용 기준**

- 충돌 파일 2개 이상에서 “모두 건너뛰기” 선택 시 이후 충돌 파일은 추가 확인 없이 건너뛴다.
- 진행률 창에서 취소 시 안전한 중단 상태와 결과 요약을 표시한다.

## FR-9. 삭제와 휴지통

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-9.1 | 선택 항목 삭제를 지원해야 한다. | Must |
| FR-9.2 | 휴지통 이동과 영구 삭제를 구분해야 한다. | Must |
| FR-9.3 | 삭제 전 항목 목록과 총 크기를 보여주는 확인 UI를 제공해야 한다. | Must |
| FR-9.4 | 디렉토리 재귀 삭제를 지원해야 한다. | Must |
| FR-9.5 | 휴지통 이동은 플랫폼별 휴지통/Recycle Bin API를 사용해야 한다. | Must |
| FR-9.6 | 영구 삭제는 더 강한 경고와 기본 취소 선택을 제공해야 한다. | Must |
| FR-9.7 | 휴지통 이동, 이름 변경, 이동처럼 복구 가능한 작업은 Undo 후보로 기록할 수 있다. | Should |
| FR-9.8 | 영구 삭제는 Undo 대상에서 제외하거나 복구 불가능함을 명확히 표시해야 한다. | Must |

**수용 기준**

- 휴지통 삭제 성공 후 항목이 목록에서 사라지고 토스트/알림이 표시된다.
- 영구 삭제는 진행률을 표시하며 취소 가능해야 한다.
- 권한 오류 발생 시 나머지 항목 처리 정책이 명확히 동작한다.

## FR-10. 새 폴더, 이름 변경, 속성

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-10.1 | 새 디렉토리 생성을 지원해야 한다. | Must |
| FR-10.2 | 파일/디렉토리 이름 변경을 지원해야 한다. | Must |
| FR-10.3 | 빈 이름, 중복 이름, 권한 부족 오류를 검증해야 한다. | Must |
| FR-10.4 | 생성/이름 변경 완료 후 해당 항목에 포커스를 이동해야 한다. | Should |
| FR-10.5 | 파일/디렉토리 속성 보기 UI를 제공해야 한다. | Must |
| FR-10.6 | 속성에는 이름, 경로, 타입, 크기, 수정일, 권한, 디렉토리 하위 항목 수를 포함해야 한다. | Must |
| FR-10.7 | 속성 창에서 경로 복사, Finder/Explorer에서 보기 같은 보조 액션을 제공할 수 있다. | Should |
| FR-10.8 | 이름 변경은 다이얼로그뿐 아니라 리스트 내부 인라인 편집으로도 제공할 수 있다. | Should |
| FR-10.9 | 일괄 이름 변경은 prefix/suffix, 번호 붙이기, 확장자 변경, 정규식 치환을 후속 기능으로 검토한다. | Could |

**수용 기준**

- 이름 변경에서 기존 이름이 입력창에 미리 채워진다.
- 디렉토리 속성은 하위 파일 수와 총 크기를 계산해 표시한다.
- 파일 정보 단축키·메뉴·컨텍스트 메뉴는 추가 확인 없이 즉시 속성 조회를 시작한다.
- 속성과 충돌 비교의 수정일은 기기 현지 시간 기준 `YYYY-MM-DD HH:mm:ss`로 표시하며, 소수 초와 타임존 표기는 숨긴다.

## FR-14. 압축 파일 처리

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-14.1 | zip, tar, tar.gz/tgz, tar.zst/tzst, 7z, jar, war 형식 감지를 지원해야 한다. | Must |
| FR-14.2 | 선택 파일/폴더 압축 생성을 지원해야 한다. 기본 저장 위치는 선택 항목이 있는 활성 패널의 현재 디렉터리다. 기본 이름은 단일 폴더는 폴더명, 단일 파일은 원래 확장자를 포함한 파일명, 복수 항목은 상위 폴더명을 사용한다. 대상 위치에서 이름이 겹치면 `(2)`, `(3)` 순으로 번호를 붙인다. | Must |
| FR-14.3 | 압축 해제를 지원해야 한다. | Must |
| FR-14.4 | 압축 파일을 `archive.zip:/` 형태의 가상 디렉터리로 열어 내부 목록을 탐색할 수 있어야 한다. | Must |
| FR-14.5 | 압축 파일을 패널처럼 탐색하는 UX를 제공할 수 있다. | Should |
| FR-14.6 | zip/7z처럼 암호 지원 형식은 암호 설정/입력을 지원해야 한다. 암호화된 압축 내부 항목을 복사할 때 암호가 없으면 작업 시작 전에 암호 입력 창을 표시한다. | Must |
| FR-14.7 | 압축 해제 시 기존 파일 충돌을 감지하고 처리 옵션을 제공해야 한다. | Must |
| FR-14.8 | 압축/해제 진행률과 취소를 지원해야 한다. 압축 생성은 사전 스캔 후에도 작업 중 처리량을 갱신해야 한다. | Must |
| FR-14.9 | 압축 해제는 zip-slip 같은 경로 탈출 공격을 방지해야 한다. | Must |
| FR-14.10 | 압축 내부 목록이 매우 클 경우 탐색 UI가 멈추지 않도록 표시/로딩 전략을 제한하고 “일부만 표시” 상태를 알려야 한다. 같은 압축 파일 내 폴더 이동은 목록을 재사용하며, 원본 파일 변경이나 명시적 새로고침 시 다시 읽는다. | Should |
| FR-14.11 | 압축 파일 더블클릭/Enter 기본 동작은 가상 디렉터리 진입이며, 컨텍스트 메뉴에서 압축 해제를 제공해야 한다. | Should |

**수용 기준**

- 암호가 필요한 압축 파일은 암호 입력 UI를 표시한다.
- 악의적인 `../` 경로가 포함된 압축 파일은 대상 폴더 밖으로 파일을 쓰지 못한다.
- 압축 생성 대상 파일명이 이미 존재하면 사용자에게 다른 경로를 요구한다.

## FR-15. 외부 프로그램 연동

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-15.1 | OS 기본 연결 프로그램으로 파일 열기를 지원해야 한다. | Must |
| FR-15.2 | 파일을 시스템 파일 관리자에서 위치 표시(Finder/Explorer reveal)할 수 있어야 한다. | Should |
| FR-15.3 | 사용자는 기본 편집기 또는 선호 앱을 설정할 수 있어야 한다. | Should |
| FR-15.4 | 터미널 에디터 실행 기능은 GUI에서는 “외부 에디터로 열기”로 재해석한다. | Should |
| FR-15.5 | 현재 경로에서 셸/터미널 명령 실행을 지원할 수 있다. | Could |
| FR-15.6 | 외부 명령 실행은 작업 디렉토리, 종료 코드, 오류 메시지를 명확히 표시해야 한다. | Must if implemented |
| FR-15.7 | 플랫폼별 기본 앱 열기 방식은 macOS, Windows, Linux 각각에서 동작해야 한다. | Must |
| FR-15.8 | “경로 복사”, “파일명 복사”, “절대경로/상대경로 복사”를 컨텍스트 메뉴와 단축키로 제공할 수 있다. | Should |
| FR-15.9 | 외부 앱으로 드래그 아웃할 때 OS 파일 드래그를 전달할 수 있다. | Could |

**수용 기준**

- 파일 열기 실패 시 원인과 해결 힌트를 표시한다.
- 디렉토리나 `..` 항목을 “파일 편집” 대상으로 선택하면 사용자에게 불가 사유를 표시한다.
