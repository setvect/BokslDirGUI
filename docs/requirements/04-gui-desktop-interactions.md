# 04. GUI/데스크톱 상호작용: 마우스, 컨텍스트 메뉴, DnD, 미리보기, 작업 큐

## FR-16. 메뉴, 툴바, 컨텍스트 메뉴

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-16.1 | 상단 메뉴는 파일, 편집, 보기, 도구, 설정, 도움말 범주를 제공해야 한다. | Must |
| FR-16.2 | 메뉴 항목은 단축키 표시와 활성/비활성 상태를 가져야 한다. | Must |
| FR-16.3 | 주요 파일 작업은 패널 컨텍스트 메뉴에서도 접근 가능해야 한다. | Must |
| FR-16.4 | 툴바 또는 액션바는 자주 쓰는 작업(복사/이동/삭제/새 폴더/새로고침/검색)을 제공해야 한다. | Should |
| FR-16.5 | 메뉴/툴바/단축키/도움말은 같은 액션 정의를 참조해 불일치를 줄여야 한다. | Must |
| FR-16.6 | GUI에서는 마우스 클릭, 더블클릭, 우클릭, 드래그 앤 드롭을 지원해야 한다. | Should |

**컨텍스트 메뉴 기본 항목**

- 열기
- 기본 앱으로 열기
- 외부 에디터로 열기
- Finder/Explorer에서 보기
- 복사
- 이동
- 이름 변경
- 휴지통으로 이동
- 영구 삭제
- 압축하기
- 압축 풀기
- 경로 복사
- 파일명 복사
- 속성 보기

**수용 기준**

- 메뉴에서 실행한 복사와 단축키로 실행한 복사는 같은 검증/충돌/진행률 흐름을 사용한다.
- 비활성 상태의 메뉴 항목은 실행되지 않는다.

## FR-17. 단축키와 액션 시스템

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-17.1 | 모든 사용자 액션은 단일 액션 레지스트리 또는 동등한 중앙 정의로 관리해야 한다. | Must |
| FR-17.2 | 단일 키 단축키와 시퀀스 단축키를 지원해야 한다. | Must |
| FR-17.3 | 시퀀스 단축키는 제한 시간 내 두 번째 키가 입력되지 않으면 해제되어야 한다. | Should |
| FR-17.4 | 기존 핵심 단축키 호환성을 제공해야 한다. | Should |
| FR-17.5 | 단축키 도움말은 액션 레지스트리에서 자동 생성되어야 한다. | Should |
| FR-17.6 | 사용자는 단축키를 커스터마이징할 수 있어야 한다. 기존 요구 문서에는 있으나 구현 근거는 약하므로 후속 기능으로 둔다. | Could |
| FR-17.7 | 단축키 충돌은 설정 저장 전에 검증해야 한다. | Must if implemented |

**기본 호환 단축키 후보**

| 범주 | 키 | 동작 |
| --- | --- | --- |
| 탐색 | `j/k`, `↑/↓` | 위/아래 이동 |
| 탐색 | `h/l`, `←/Enter` | 상위/진입 |
| 탐색 | `gg/G`, `Home/End` | 맨 위/맨 아래 |
| 패널 | `Tab` | 활성 패널 전환 |
| 파일 | `y/x` | 복사/이동 |
| 파일 | `d/D` | 휴지통 삭제/영구 삭제 |
| 파일 | `a/r/i` | 새 폴더/이름 변경/속성 |
| 파일 | `o/e/:` | 기본 앱 열기/외부 에디터/명령 실행 |
| 선택 | `Space`, `Ctrl+A`, `v`, `u` | 선택 토글/전체 선택/반전/해제 |
| 보기 | `/`, `.`, `Ctrl+R` | 필터/숨김 파일/새로고침 |
| 정렬 | `sn/ss/sd/se/sr` | 이름/크기/날짜/확장자/순서 |
| 탭/목록 | `tn/tx/tt/th/tb` | 탭 생성/닫기/목록/히스토리/북마크 |
| 위치 | `gm/gp` | 마운트 포인트/경로 이동 |
| 압축 | `zc/zx/za` | 압축/해제/자동 해제 |
| 도움말 | `?` | 단축키 도움말 |

## FR-18. 도움말과 온보딩

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-18.1 | 앱 내 단축키 도움말을 제공해야 한다. | Must |
| FR-18.2 | 도움말은 카테고리별로 액션을 정리해야 한다. | Must |
| FR-18.3 | 도움말 내 검색을 지원해야 한다. | Should |
| FR-18.4 | 검색 결과 개수와 매칭 강조를 제공해야 한다. | Should |
| FR-18.5 | GUI 초보자를 위한 첫 실행 안내 또는 빈 상태 가이드를 제공할 수 있다. | Could |
| FR-18.6 | About 다이얼로그를 제공해야 한다. | Should |
| FR-18.7 | 도움말은 키보드 경로뿐 아니라 메뉴/마우스 경로도 함께 설명해야 한다. | Should |

**수용 기준**

- 사용자가 `?` 또는 도움말 메뉴를 열면 현재 사용 가능한 단축키와 설명이 표시된다.
- 검색어 입력 시 키/설명 기준으로 부분 일치 결과가 필터링된다.

## FR-28. 마우스 이벤트

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-28.1 | 단일 클릭은 포커스/선택을 변경해야 한다. | Must |
| FR-28.2 | 더블클릭은 항목 타입별 기본 액션을 실행해야 한다. | Must |
| FR-28.3 | 우클릭은 현재 항목 또는 빈 영역에 맞는 컨텍스트 메뉴를 표시해야 한다. | Must |
| FR-28.4 | 빈 영역 우클릭은 새 폴더, 붙여넣기, 터미널/시스템 파일 관리자 열기 같은 위치 중심 액션을 제공할 수 있다. | Should |
| FR-28.5 | Shift 클릭 범위 선택과 Cmd/Ctrl 클릭 다중 선택을 지원해야 한다. | Must |
| FR-28.6 | 드래그 박스 선택 또는 리스트 행 드래그 선택을 지원할 수 있다. | Should |
| FR-28.7 | 마우스 hover는 항목 툴팁, 전체 경로, 잘린 파일명 표시를 제공할 수 있다. | Could |
| FR-28.8 | 마우스 조작은 키보드 포커스와 접근성 포커스를 깨뜨리지 않아야 한다. | Must |

**더블클릭 기본 동작 후보**

| 항목 | 기본 동작 |
| --- | --- |
| 폴더 | 해당 폴더 진입 |
| 일반 파일 | OS 기본 앱으로 열기 |
| 실행 파일 | 확인 후 실행 또는 기본 앱 열기 정책 적용 |
| 압축 파일 | 가상 디렉터리 진입 |
| 이미지/텍스트/PDF | 미리보기 패널이 켜져 있으면 선택, 꺼져 있으면 기본 앱 열기 |

## FR-29. 드래그 앤 드롭

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-29.1 | 한 패널에서 반대 패널로 항목을 드래그해 복사/이동을 시작할 수 있어야 한다. | Should |
| FR-29.2 | 같은 패널 안에서 항목을 폴더 위로 드래그해 이동할 수 있어야 한다. | Should |
| FR-29.3 | 외부 Finder/Explorer에서 앱으로 파일을 드롭할 수 있어야 한다. | Should |
| FR-29.4 | 앱에서 외부 Finder/Explorer 또는 다른 앱으로 파일 드래그를 전달할 수 있어야 한다. | Could |
| FR-29.5 | 드롭 전 대상 폴더와 예상 작업(복사/이동/금지)을 시각적으로 표시해야 한다. | Must if implemented |
| FR-29.6 | 드롭 후에는 일반 복사/이동과 같은 충돌 처리, 진행률, 취소 흐름을 사용해야 한다. | Must if implemented |
| FR-29.7 | 앱 외부에서 들어온 드롭은 권한/경로 유효성 검증을 거쳐야 한다. | Must if implemented |

**수용 기준**

- 드롭 대상이 유효하지 않으면 작업을 시작하지 않고 금지 피드백을 표시한다.
- 드래그 앤 드롭 파일 작업도 작업 큐와 오류 요약에 기록된다.

## FR-30. 보기 모드와 미리보기

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-30.1 | 상세 목록 보기를 기본으로 제공해야 한다. | Must |
| FR-30.2 | 간단 목록, 아이콘 보기, 썸네일 보기를 제공할 수 있다. | Should |
| FR-30.3 | 미리보기 패널을 제공할 수 있다. | Should |
| FR-30.4 | 빠른 보기 키 또는 버튼으로 선택 파일 미리보기를 열 수 있다. | Should |
| FR-30.5 | 이미지 미리보기는 해상도와 파일 크기 정보를 함께 표시할 수 있다. | Should |
| FR-30.6 | 텍스트/Markdown/코드 파일은 인코딩 오류에 안전하게 대응하고 syntax highlight를 제공할 수 있다. | Could |
| FR-30.7 | PDF/동영상은 플랫폼 지원 범위 안에서 썸네일 또는 기본 정보만 표시할 수 있다. | Could |
| FR-30.8 | 압축 파일 가상 디렉터리는 내부 목록과 항목 수/총 크기를 파일 패널 맥락에서 표시해야 한다. | Should |
| FR-30.9 | 미리보기 생성은 파일 작업과 탐색 UI를 블로킹하지 않아야 한다. | Must if implemented |

**수용 기준**

- 미리보기 불가능한 파일은 실패가 아니라 “미리보기 지원 안 함” 상태로 표시된다.
- 큰 파일 미리보기는 크기 제한 또는 사용자 확인을 거친다.

## FR-31. 작업 큐, 알림, Undo

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-31.1 | 여러 파일 작업을 작업 큐로 관리할 수 있어야 한다. | Should |
| FR-31.2 | 작업 큐는 대기/진행/완료/실패/취소 상태를 표시해야 한다. | Should |
| FR-31.3 | 사용자는 작업을 취소할 수 있어야 한다. | Must |
| FR-31.4 | 작업 일시정지/재개는 후속 기능으로 검토한다. | Could |
| FR-31.5 | 작업 완료 후 토스트와 시스템 알림을 제공할 수 있다. | Should |
| FR-31.6 | 완료 알림에서 대상 위치 열기 또는 결과 보기 액션을 제공할 수 있다. | Should |
| FR-31.7 | 이동, 이름 변경, 휴지통 삭제 같은 복구 가능한 작업은 Undo를 제공할 수 있다. | Should |
| FR-31.8 | Undo는 대상 파일이 이후 변경된 경우 충돌/불가 상태를 명확히 표시해야 한다. | Must if implemented |

**수용 기준**

- 작업 큐에 등록된 작업은 앱의 단일 진행률/오류 정책을 따른다.
- 시스템 알림은 사용자가 끌 수 있어야 한다.

## FR-32. 듀얼 패널 고급 기능

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-32.1 | 좌우 패널 경로 스왑을 제공할 수 있다. | Should |
| FR-32.2 | 한쪽 패널 경로를 반대쪽 패널로 복사하는 액션을 제공할 수 있다. | Should |
| FR-32.3 | 패널 동기화 모드는 한쪽에서 하위 경로 이동 시 반대쪽도 대응 상대 경로로 이동할 수 있다. | Could |
| FR-32.4 | 좌/우 폴더 비교 기능을 제공할 수 있다. | Could |
| FR-32.5 | 폴더 비교는 한쪽에만 있는 파일, 같은 이름이지만 크기/수정일이 다른 파일을 표시해야 한다. | Must if implemented |
| FR-32.6 | 동기화 복사는 좌→우, 우→좌 방향을 명확히 선택하게 해야 한다. | Could |
| FR-32.7 | 양방향 동기화는 데이터 손실 위험이 커서 별도 설계/검증 후 도입해야 한다. | Could |

## FR-33. 생산성 확장

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-33.1 | 명령 팔레트를 제공할 수 있다. | Could |
| FR-33.2 | 명령 팔레트는 액션명, 단축키, 메뉴 경로를 검색해 실행해야 한다. | Must if implemented |
| FR-33.3 | 인라인 이름 변경을 제공할 수 있다. | Should |
| FR-33.4 | 일괄 이름 변경을 제공할 수 있다. | Could |
| FR-33.5 | 클립보드 기반 파일 복사/붙여넣기를 제공할 수 있다. | Should |

- 생산성 확장 기능은 기존 파일 작업 안전 정책을 우회하지 않는다.
- 명령 팔레트의 실행 가능 상태는 메뉴/단축키와 같은 액션 상태를 사용한다.
