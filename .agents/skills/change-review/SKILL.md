# 변경 검토와 국소 정리

- 목표: 이번 기능의 이해·수정에 필요한 범위 축소
- 기존 구조가 적절한 경우 리팩토링 없이 완료
- 특정 언어·프레임워크·테스트 명령의 전역 강제 제외

## 범위와 실행 모드

- 적용 지침과 변경 범위 확인
  - `AGENTS.md`, 사용자 요청, staged·unstaged diff, 새 파일 확인
  - 변경 코드와 직접 관련된 호출부·타입·테스트부터 검토
- 허용된 작업 범위 준수
  - 검토만 요청받거나 커밋 준비 중 호출된 경우 우선 검토만 수행
  - 이미 허용된 구현 작업의 마무리인 경우 해당 범위 안의 동작 보존 정리 허용
  - 이 스킬을 근거로 관련 없는 변경 수행 금지
- 기존 검토·테스트 근거 재사용
  - 현재 작업에 동일한 최종 코드의 근거가 있는 경우 재사용
  - 이후 수정된 부분과 영향받는 경계만 재확인
  - 커밋 해시·파일 목록의 일치만으로 근거의 최신성 판단 금지

## 판단 기준

- 프로젝트 규칙을 기준으로 변경과 관련된 항목만 검토
- 책임과 의존 방향
  - 역할에 맞는 구현 위치, 화면·입력 경로별 실행 로직 복제 여부 확인
  - 순환 의존·내부 상태 우회 여부 확인
- 상태와 수명주기
  - 상태 소유자 증가·함께 갱신하는 상태의 분산 여부 확인
  - 비동기 응답·취소·이벤트 구독 종료 처리의 유지 여부 확인
- 중복과 추상화
  - 같은 업무 규칙의 수정 위치 증가 여부 확인
  - 새 인터페이스·파일의 호출 구조 단순화 효과 확인
  - 줄 수·파일 수만을 근거로 한 분리 금지
  - 항상 함께 바뀌는 작은 모듈의 통합 허용
- 계약과 검증
  - 기존 동작·공개 계약·데이터 형식 보존 여부 확인
  - 관련 테스트를 통한 중요한 실패 경로 검증 가능 여부 확인

## 처리와 종료

- 발견 사항의 위치·발생 조건 또는 변경 부담의 구체적 근거·영향·검증 방법 기록
  - 추측과 재현된 결함 구분
- 허용된 국소 정리의 작은 단위 적용
  - 관련 없는 포맷·이름 변경 제외
  - 버그 수정 시 동작 보존 정리와 구분, 재현·회귀 근거 확보
- 큰 개선의 현재 작업 필요성 판단
  - 대상: 공개 계약·상태 소유권 변경, 여러 기능 재설계, 새 라이브러리 도입
  - 현재 범위 밖인 경우 구체적 이점·영향 범위를 포함한 후속 항목 기록
  - 취향에 따른 개선·후속 후보만을 근거로 정상적인 커밋 차단 금지
- 실제 변경에 맞는 검증과 프로젝트 필수 검사 실행
  - 수정 후 최종 diff 재확인
  - 실패·미검증을 통과로 기록 금지
- 최종 변경 범위의 검토 결과 확보 시 종료
  - 임의의 정리 목표를 채우기 위한 범위 확대 금지
  - 이 스킬에서 스테이징·커밋·푸시 수행 금지

## 결과 보고

- 기본 기록 위치: 대화
- 검토 범위·정리 내용 또는 수정 없음의 이유·검증 결과의 간결한 보고
- 확인된 미해결 결함과 선택적 후속 개선 구분
- 반복되는 실제 구조 문제가 후속 작업에 도움이 되는 경우에만 기존 프로젝트 문서에 근거 기록
- 매 실행마다 별도 보고서 파일 생성 금지
